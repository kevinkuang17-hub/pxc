# 节点控制台（PXC）

用一个控制台替换 3X-UI 主控：用户、套餐、线路只在控制台维护，**单向**推送到各台单机版 3X-UI；多台服务器在订阅和流量上合并成一套服务。按《节点控制台 PRD》实现，本版覆盖 PRD 建议先做的 **M1 + M2**，加上独立订阅服务、CRM 对接和一键部署。

### v0.2.1

- **命名约定**：服务器、线路、线路组都按“地区代码 + 字母”：US A、HK A、JP A……A 是这个地区第一台，B 第二台，以此类推。新增服务器 / 一键接入时名字留空，会按地区自动排到下一个字母；一键建线路默认用服务器名。
- **地区组**：分流方案和需求开关里的策略写地区代码（US / HK / JP …）。生成订阅时自动建一个地区组（如 🇺🇸 US），里面按 US A → US B → … 顺序主备切换：A 不通才用 B。v0.2.0 里写的“美国 / 香港”不用改，自动当作 US / HK。
- **升级不覆盖数据**：升级只换程序目录，配置、数据库、加密密钥、Logo 都不动；升级前先停服务、完整备份（保留最近 10 次）；升级后逐表核对数据条数，少了一条或服务起不来，自动还原数据并回到旧版本。数据库结构变化只会“加”，不会删列删表。一键接入脚本遇到已经装了 3X-UI 的服务器会直接退出，不重装、不改它的端口账号和数据库。

### v0.3.0

- **Hysteria2**：新版 Xray（3X-UI 3.x 自带）原生支持 Hysteria2，并能按用户统计流量，所以直接走 3X-UI 推送，不需要另装 sing-box。入站协议选“Hysteria2”，或「一键建线路」选 Hysteria2（需要证书，UDP 端口自动分配）；订阅四种格式都带上（`hysteria2://`、Clash `hysteria2`、sing-box `hysteria2`）。需要节点上的 3X-UI 是 3.x 版本。
- **落地故障自动切换**：线路可设“备用出站”。控制台每分钟测一次每个落地，主落地连续 3 次连不上就自动切到备用并推送到入口服务器，连续 3 次恢复后切回；所有落地同时连不上时判断为控制台网络问题，不切换。订阅里的地区旗帜跟着实际出口走。
- **经线路实测出口 IP 和解锁**：控制台本机用 Xray 经每条线路访问 IP 查询接口和 ChatGPT / Claude / Gemini / Netflix / YouTube Premium，每 3 小时一次，出口 IP 和预期不符、解锁情况变化都会告警。为此控制台会在接管中的服务器入站里加一个探测账号（不计流量、不显示在用户里，观察期不加）；「监控与核对」页可一键更换。控制台需要 xray 程序，安装脚本会自动下载，也可执行 `pxc install-xray`。
- **兼容新版 3X-UI 用户接口**：新版 3X-UI 把用户接口挪到了 `/panel/api/clients/`，控制台自动识别，新旧版本都能推送。
- 生成的 VLESS（TCP+TLS+Vision / XHTTP / Reality）、Trojan、Hysteria2 配置都用真实 Xray 内核跑通过（服务端 + 客户端互通）。

### v0.4.0

- **国内分运营商探针**：「国内探针」页生成一行命令，在各地的 KWRT / OpenWrt 路由器上执行。路由器每 5 分钟测一遍所有线路（TLS / TCP 握手），回报控制台。至少 2 个探针都不通、而控制台（海外）测得通 → 判断为被封，告警并提示“一键换 IP”，开了自动摘除就先从订阅去掉，国内恢复（或探针都没有新数据）后自动加回；某个运营商全不通 → 告警，并在订阅里把这条线路排到同组后面。
- **Hysteria2 自动摘除**：每 5 分钟用本机 Xray 经 Hysteria2 线路实际请求一次，连续 3 次失败从订阅摘除、恢复后加回。
- **更多客户端**：订阅新增 Stash、Surge、Loon、Quantumult X（浏览器引导页有一键导入）。Surge / Loon / QX 不支持 Reality、XHTTP、gRPC 和 Vision，只下发它们能用的线路；没有 geosite 的客户端，广告 / AI / 流媒体分类自动换成公开规则列表。
- **保守模式**：敏感时期在「监控与核对」点“保守模式：开”，所有订阅只保留 Reality 和走 Cloudflare 的线路；单个订阅地址加 `&safe=1` 也行。
- **多管理员**：「管理员」页添加账号，三种角色：超级管理员（全部）、运维（不能动管理员 / 安全与对接 / 外观通知 / Cloudflare 账号）、只读客服（只能看，看不到密钥、不能导出）。可停用（立即下线）、重置密码、重置两步验证；至少保留一个超级管理员。
- **通行密钥（Passkey）**：右上角用户名 →「我的账号」添加，之后登录第二步和敏感操作可以用指纹 / 面容 / Windows Hello 代替 6 位码（浏览器要求控制台用 HTTPS 域名打开）。也可在这里改自己的密码。
- **按应用流量**（默认关，在「外观与通知」打开）：把 AI / 视频 / 社交 / 下载更新的流量分开计数，报表里看。只统计从服务器直接出去的流量；规则放在路由表最后、出站复制默认出口的设置，出口不会变。
- **异常检测**：在线设备数超过上限、流量突增（24 小时超过平时日均 5 倍）、订阅被很多 IP 拉取（疑似外泄，可选自动换订阅地址），都会告警并在报表页列出。
- **VPS 成本**：服务器资料里填商家、月费、下次续费日期；报表页算每 GB 成本，续费前 7 天、1 天提醒。
- **运营日报 / 周报**：每天（或每周一）定时发到 Telegram 和 Webhook：流量、用量前五、离线服务器、摘除的线路、即将到期、续费、成本、异常次数。
- **配置历史**：服务器详情 →「配置历史」，每次推送和巡检发现变化都记一版（密钥只留后 4 位），可以逐行对比两版差异。
- **内核灰度升级**：「内核升级」页选版本 → 先升一台金丝雀，观察 30 分钟没问题再逐台升级；每台升级后检查 Xray 运行、版本、线路握手，不通过自动装回原版本并暂停。
- **一键部署改为直接从 GitHub 安装**，不用上传任何文件；也提供 Docker Compose 方式。

## 一、安装控制台

装在一台**不对用户公开**的服务器上（PRD 待定问题 1：可以和现在的 3X-UI 主控同机，端口不冲突即可）。SSH 登录服务器，用 root 粘贴这一行（和装 3X-UI 一样，不用上传任何文件）：

```
bash <(curl -fsSL https://raw.githubusercontent.com/kevinkuang17-hub/pxc/main/scripts/install.sh)
```

以后升级：服务器上输入 `pxc update`（或再执行一次上面这行）。升级只换程序，数据、配置、密钥都不动；升级前自动完整备份，升级后核对数据条数，不对就自动还原。

代码推到 GitHub 的 main 分支后，GitHub Actions 会自动跑全部测试（含真实 Xray 互通），通过才发布新版本；测试不过不会发布，服务器上的 `pxc update` 只会拿到测试通过的版本。

**Docker 方式（可选）**：`git clone https://github.com/kevinkuang17-hub/pxc && cd pxc && cp docker/env.example .env`，改 `.env` 里的登录路径，然后 `docker compose up -d --build`，再执行 `docker compose exec web python -m pxc.cli create-admin admin` 拿到初始密码。数据在 `./data`。

安装完会打印 **登录地址、账号、随机密码**。第一次登录必须用手机验证器（Google Authenticator / Microsoft Authenticator / 1Password）绑定，并保存 10 个备用码。

> 控制台不要直接暴露公网：建议服务器装 Tailscale，只用内网地址访问，并在「外观与通知 → 后台 IP 白名单」填 `100.64.0.0/10`。把自己关在外面时，在服务器上执行 `pxc clear-allowlist`。

## 二、接管现有服务器（按 PRD 迁移步骤）

1. **每台节点**：确认 3X-UI 是单机模式、面板端口不是 2096、面板防火墙放行控制台 IP。
2. 控制台「服务器 → 新增」：填名称、地区（HK/SG…）、节点域名、面板地址（**含端口和路径**，如 `http://100.64.0.5:23456/abc`）、面板账号密码。保存时会自动测连接。先保持“只读观察”。
3. 「服务器 → 从 3X-UI 导入」：**勾选全部服务器一起导入**（落地在别的服务器上，一起导才能对上）。用户和线路关系以服务器上实际运行的为准（HK A 443 实际 29 人就导 29 人）。
4. 「线路组」建 香港 / 日本 / 新加坡 / 美国 …，把线路放进去；「套餐」按现在的分配归纳 2–4 个，给用户选套餐；对不上的保留“额外加的线路”。
5. **只读观察 7 天**：每 5 分钟自动比对，概览页“需要处理”为 0、服务器详情“差异 0”。
6. **试点 HK D**：在 3X-UI 主控里**停用**（不要删除）HKD 节点 → 控制台里 HK D「切换为控制台接管」。试：加减用户、改套餐、在服务器面板上故意删一个用户（5 分钟内会被补回）、把落地密钥故意改错（会被校验拦住）。
7. 切订阅（见第三节），再每天最多 2 台逐台接管：先落地（JP A、KR A、US C LD、SG），再入口，HK A 最后。
8. 全部稳定 14 天后停用 3X-UI 主控。

**回退**：控制台里把这台切回“只读观察”，3X-UI 主控里重新启用节点、订阅域名指回主控。服务器上的 Xray 配置不变。

接管时控制台会把原来手写的落地出站和“入站→落地”规则换成 `px-` 开头的同等规则（出口不变），以后改端口、删入站都不会再丢规则。

## 三、订阅服务（独立一台，走 Cloudflare）

1. 控制台「安全与对接 → 添加订阅节点」，填一个名称和**订阅服务器能访问到的控制台地址**，得到一行命令。
2. 在订阅服务器上用 root 粘贴执行。默认监听 80，且只允许 Cloudflare 访问。
3. Cloudflare 把 `clbstar.vertex-astra.com` 解析到这台服务器（开小黄云）。默认是 80 端口回源，需要用 Cloudflare 的 Configuration Rules 只给这个子域设 SSL“灵活”；想按 PRD 用 Full (strict)，在订阅服务器依次执行 `pxc cert clbstar.vertex-astra.com 你的CF令牌`、`pxc port 443`、`pxc cf-firewall`。
4. 控制台「外观与通知 → 订阅对外地址」填 `https://clbstar.vertex-astra.com`。

订阅服务不存数据，每 20 秒从控制台只读同步并缓存到本地；控制台连不上时继续用缓存出订阅。IP 被封：新机器上再执行一次第 1–2 步，改 DNS 即可。旧 3X-UI 订阅地址 `/sub/<subId>` 继续可用，用户不用改（3X-UI 里订阅路径改过的话，在订阅服务器执行 `pxc legacy-path /你的路径/`）。

订阅地址格式：`https://订阅域名/s/<16位令牌>`，可加 `?target=clash|singbox|v2ray|shadowrocket|stash|surge|loon|qx`，加 `&safe=1` 只要 Reality / CDN 线路；OpenClash 只要节点用 `?target=clash&nodes=1`（proxy-provider）。

## 四、新服务器一键接入

「服务器 → 一键接入新服务器」：填名称、地区、节点域名、控制台地址（建议 Tailscale 内网），可选 Tailscale 授权密钥、Cloudflare 令牌 → 得到一行命令，在新 VPS 上 root 粘贴。完成后服务器自动出现在列表里（直接是接管模式），再去「一键建线路」。

## 五、v0.2 上手

1. **Cloudflare**：左侧「Cloudflare」添加 API 令牌（“编辑区域 DNS”模板，选 startech.qzz.io 和 vertex-astra.com）。之后服务器详情页有「同步解析 / 接管这条记录 / 一键换 IP」。想让核对也检查 SSL 模式，令牌再加 Zone Settings:Read。
2. **监控**：「监控与核对」页。部署后控制台每分钟自动探测；页面右上角可关掉“自动摘除”。
3. **分流规则**：「分流规则」里已建好“标准分流 / 外贸办公 / 全局代理”。到「套餐」给套餐选默认方案；个别用户在用户编辑页的“分流”里换方案或勾需求开关。方案里写的“美国”“香港”是线路组名，用户没有这个组就自动走默认代理组。
4. **报表**：「流量报表」。

## 七、需要你在真实环境确认的地方

- **3X-UI 接口版本**：按 3X-UI 2.x/3.x 公开的 `/panel/api/` 接口和 `/panel/xray/` 模板接口实现（旧路径自动兜底）。上线前在 HK D 上跑一次「测试连接 → 导入这台的配置 → 立即比对」，差异应为 0；若报“面板没有这个接口”，把报错发我。
- **3X-UI 会自动把入站 tag 设成 `inbound-端口`**，控制台的稳定标签写在入站备注里，路由规则推送时按当前端口换算，所以改端口不会丢规则。
- Shadowrocket 与 Reality 的兼容、各客户端实测矩阵（PRD F15）还需要逐个用最新版验证；Surge / Loon / Quantumult X 的配置按各自官方格式生成，没有在真机上测过，第一次用请先导入一个账号试一下。
- 按应用流量要求 3X-UI 有“出站流量”功能（2.x 新版本 / 3.x）；设备超限检测要求 3X-UI 开了 IP 记录（“IP 限制”用到的访问日志）。
- 内核灰度升级调用 3X-UI 面板“切换 Xray 版本”接口，建议先拿用户最少的一台做金丝雀。
- PRD 待定问题 2（套餐划分）、3（告警发 Telegram 还是企业微信）：本版支持 Telegram 和 CRM Webhook，企业微信可由 CRM 接 Webhook 转发。
